# 商品生成プロンプトの購入UU自動選抜

## 仕様

- 実験ID: `design-prompts-v1`。指示本文を変更するときは実験IDも更新し、旧売上を引き継がない。
- 10案: ミニマル / 線画 / 墨・筆致 / 幾何学 / ヴィンテージ / 文字とシンボル / 有機的な曲線 / 躍動感 / 遊び心 / 抽象グラフィック。
- 本文の正本: `store/src/prompt_selection.rs` の `PATTERNS`。
- 自動生成 `generate_one`、管理者の自然言語生成 `admin_nl_add`、Web/iOS共通 `public_make` に適用。持ち込み画像には適用しない。既存画像のリミックスや補正は新規試験への割当対象外。
- 指定した題材・スタイル・色・文言と、DTG白背景/AOP全面/刺繍等の製造制約が優先。元のプロンプトを保持して制作方向を追記する。
- 採用案がない間は、成功して保存された生成商品数の少ない案から選ぶ。同数ならseedで分散。同時実行時に厳密なラウンドロビンを保証するものではない。
- **同じプロンプトから作った商品全体で購入UUが4人以上なら仮採用。** 次の生成時に再集計し、80%の確率で採用済み案、20%で未採用案から選択。試行枠は未採用案の中で生成数が少ない案を優先。生成件数・頻度・予算上限は増やさない。
- 採用ゼロなら100%試行、全10案採用済みなら100%採用案。80/20はseedごとの確率で、5回ごとの厳密な4:1配分ではない。SHA-256で枠と候補の選択を独立に分散し、同じseedと集計状態なら再起動後も同じ選択。
- 選択方針IDは `explore-20-v1`。指示本文は変更していないため実験IDと過去の購入実績を保持する。商品帰属にもpolicyを記録。管理APIで設定比率と現在の実効比率を確認できる。
- 返金などで4UUを下回った案は採用対象から外れる。候補ゼロなら10案の試行へ戻る。累計集計で期限なし。

## 購入UUの定義

- お客様の**購入時メールアドレス**をtrim・小文字化し、プロンプト単位で重複除外。同じメールの再購入、同一カートの複数商品・枚数は1人。別メールアドレスの同一人物までは統合できない。
- Stripeは `payment_status=paid` かつ保存セッションに `livemode=true`、正額、成功・支払済み・capture済みCharge、返金ゼロを要求する。テスト/無料/未決済/全額返金/一部返金/void/キャンセル/購入者不明は除外。
- 暗号通貨は既存のreceipt/snapshot検証後に設定される `crypto_confirmed` と、正額・一致したreference・購入時メールを使用。カードとのメール重複も除外。
- 発送失敗と決済失敗を混同せず、支払いが確認できた注文は発送前でも計上する。
- 注文の `checkout_spec_json.lines[].meta_json.prompt_selection` で帰属する。購入後の商品編集・削除で帰属を変えない。同時購入した有料の追加商品も集計する。
- 過去の帰属情報なし商品・注文は推測で割り当てない。サンプル等でも実際の正額決済ならこの定義では計上される（運営者除外リストは未導入）。

## 保存・確認

既存の `catalog_products.meta_json.prompt_selection` に実験ID、pattern ID、生成時phaseを保存。既存checkoutがそのmetaを注文snapshotに保存する。DB migrationは不要。

`GET /admin/catalog/status?token=<ADMIN_TOKEN>` の `prompt_selection` に各案の日英名・本文・生成商品数・購入UU・現在の採用状態を返す。お客様メールは返さない。集計エラーは明示し、生成時の集計エラーでは新規画像生成に進まない。

採用状態は永続注文から導出するため、独立cron・端末常駐・採用フラグ保存は不要。サーバー再起動後も同じ注文から再判定する。
